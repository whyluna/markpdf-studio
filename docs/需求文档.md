## 1. 产品概述

### 1.1 一句话定位
轻量的 macOS 原生 Markdown + PDF AI 工作台：在一个窗口内完成 **阅读并标注 PDF → 编写 Markdown → 双向关联 → 阅读 Agent 问答 → 写作 Agent 提案** 的完整闭环。

### 1.2 目标用户
- 研究生、科研人员：大量阅读 PDF 论文，需要高亮批注并沉淀为结构化笔记
- 开发者、文字工作者：需要 Typora 级体验的 Markdown 写作工具
- 共同特征：文件散落在本地文件夹，厌恶重型文献管理软件的复杂度

### 1.3 核心价值与差异化
| 维度 | 市面现状 | 本产品 |
|---|---|---|
| Markdown 编辑 | Typora 体验好但无 PDF、无项目管理 | 同等 WYSIWYG 体验 + 完整文件树 |
| PDF 标注 | PDF Expert/Skim 无笔记联动 | 标注一键沉淀为 Markdown 笔记 |
| 知识管理 | Obsidian 编辑器半吊子、PDF 只读 | 真 WYSIWYG + 学术级 PDF 标注 |
| 项目管理 | VS Code 太重、非阅读向 | 轻量 Vault，打开文件夹即用 |
| AI 辅助 | 通用聊天与文件编辑割裂，来源和落盘结果难核对 | PDF 阅读 Agent 保留来源锚点；Markdown 写作 Agent 先提案、后审查、再落盘 |

### 1.4 设计原则
1. **文件即真相**：md 存纯文本源码、PDF 标注写回标准 PDF Annotation，不使用私有数据库锁死用户数据
2. **单机离线优先**：核心功能不联网、无账号、无遥测；AI 增强（模块 8）为可选能力，仅用户显式发起时联网
3. **键盘可达**：核心操作均有快捷键与命令面板入口
4. **原生体验**：遵循 macOS HIG，系统级渲染性能

## 2. 名词约定

| 名词 | 含义 |
|---|---|
| 工作区（Vault） | 用户打开的一个本地文件夹，作为内容管理单元 |
| WYSIWYG | 所见即所得编辑模式：光标所在块显示源码，其余块实时渲染 |
| 标注（Annotation） | PDF 上的高亮、下划线、便签等标准 PDF 注释对象 |
| 回链 | Markdown 中指向某 PDF 某页的链接，点击跳转 |
| 侧car（Sidecar） | 与原文件同名的 `.json` 附属文件，存放只读模式下的标注与元数据 |

## 3. 用户场景

### 场景 A：精读论文并做笔记（主场景）
小王打开 `论文阅读` 文件夹作为工作区 → 双击 `vllm.pdf` 在第 3 页高亮三段核心论述并写了一条便签 → 点击分栏，右侧自动打开关联笔记 → 点「导出标注」，三处高亮按页码整理进 `KV Cache 调研笔记.md` 并附带页码回链 → 在笔记中点击回链，跳回 PDF 第 3 页原文位置。

### 场景 B：纯 Markdown 写作
新建 `组会汇报.md`，以所见即所得模式写作：插入对比表格、行内公式、代码块；从大纲面板拖拽调整章节顺序；导出 PDF 发给导师。

### 场景 C：批注后分享
对合作方发来的 PDF 做高亮与文字批注，标注直接写回文件，对方用 Adobe/预览打开即可看到全部批注。

> **v1.2 修订（2026-07-27，M5-D 设计输入；依据业界调研：ChatDOC 结构感知分块 / PaperQA2 RCS / NotebookLM 长上下文整文 / Cursor 上下文组装 / arXiv 2501.01880 长上下文 vs RAG 实证）**：
> 1. **上下文动态预算**：文档预算按所选模型上下文窗口计算（替代固定 8000 字头部截断——头截对「结论是什么」类问题必然失败）；每 Provider 模型可标注上下文规格，未知按保守值。装得下整文喂入（单篇论文 QA 实证优于 RAG），装不下走 2。
> 2. **结构选节 + LLM 两遍路由**（第三层上下文与超长文档共用机制，无 embedding）：md 按标题树、PDF 按书签/大纲切节；第一遍把「大纲 + 各节首句」给模型选相关节，第二遍带选中节全文作答。BM25 关键词检索可作省一次调用的快速路径。
> 3. **位置偏差排布**：选区与最相关节放 prompt 头尾，次要背景居中；system 强制「仅基于给定文档作答，不确定时明说」。
> 4. **锚点引用**：送入的节带 `[§标题]`/`[p.页码]` 标记，要求回答引用锚点，UI 点击跳转高亮（信任交互，后续批次可分步落地）。
> 5. **会话按文档隔离**：全局单会话在切文档后历史串台（模型混淆新旧文档），改每文档一线程；面板显示当前线程归属。

> v1.3/v2.0 落地说明：只读 Agent 工具调用循环已在 v1.3 完成，需批准的写作提案已在 v2.0（FR-AI.5/6）完成。仍延后评估：embedding 语义检索、md 编辑器内划词翻译。
